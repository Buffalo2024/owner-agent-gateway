# dots 接入导航

真实 dots 接入已经在维护者的小程序链路中完成授权、唤醒、执行、交付与记录。
本目录是接入导航，不是已经独立移植完成的通用适配器。

## 使用路径

1. 阅读 [本机桥接拓扑](../../docs/dots-computer-bridge.zh-CN.md)：电脑、代理、隧道与宿主授权各承担不同职责。
2. 阅读 [11 份脱敏实现与依赖](../../examples/dots-adapter/README.md)，不要直接启动含原平台导入的 TypeScript 快照。
3. 按自己的宿主支持完成 OAuth/MCP 与事件接口配置；真实凭证由主人私下输入，不放进聊天、仓库或任务正文。
4. 映射通用任务的 taskId、attempt、leaseId、inputHash 和成果 ID；原桥接的上传 URL 不直接当作通用调度器的接口。
5. 验证领取、续租、准备上传、原始字节上传、结果提交、平台回写、重复回执、失效租约和撤销。

## 移植边界

dots 不采用 Muse 的主聊天调度与按用户执行旁聊机制。当前插件调用前端不显示历史，但底层上下文存在；不能声称每个任务有隔离的新会话，也不能声称已实现同用户专属旁聊续聊。

原实现使用 PostgreSQL、native-access、protocol-adapters、agent-runtime 和平台 contracts。
这些缺失接口需要替换或依赖注入，不能以模拟成功宣称独立 dots 安装已可用。
通用仓库已有任务、可选文件存储及上下文路由；dots 宿主接入证据与通用代码测试是两个验证层。

插件隐藏前端历史，但宿主上下文实际存在；没有可验证的跨用户记忆隔离。
使用范围仍为个人或单一信任域，不承诺多租户私密服务。见 [证据摘要](../../docs/dots-evidence.json)。
